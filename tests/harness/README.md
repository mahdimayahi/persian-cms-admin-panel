# هارنس تست پنل مدیریت

تست‌های قابل‌تکرار با **دیتابیس موقت ایزوله** و **سرور مجزا** — بدون هیچ وابستگی به مسیر محیط اجرا.
همهٔ مسیرها نسبت به ریشهٔ مخزن محاسبه می‌شوند (`tests/harness/config.ts`).

## اجرا

```bash
bun run test:harness
```

خروجی موقت (gitignore شده): `db/harness/` — شامل دیتابیس موقت و `server.log`.
پایگاه دادهٔ اصلی (`db/custom.db`) و سرور توسعهٔ پورت ۳۰۰۰ هرگز دست‌نخورده نمی‌مانند.

## چه چیزی تست می‌شود؟

| سویت | فایل | پوشش |
| --- | --- | --- |
| طبقه‌بندی خطای DB | `suites/db-errors.ts` | نگاشت P2002→409، P2034→409 transient، P2028→503 transient (نه ۴۰۹)، P2024→503، علت (code) در پاسخ پنهان نمی‌شود |
| تبدیل آزمایش | `suites/analytics-concurrency.ts` | دو تبدیل **واقعاً موازی** → دقیقاً یک claim؛ **مقدار** convertedAt برابر occurredAt برنده (نه فقط شمارش ردیف)؛ تکرار eventId → DUPLICATE بی‌اثر؛ بدنهٔ null/غیرآبجکتی → INVALID نه ۵۰۰ |
| قرارداد نسخه | `suites/version-contract.ts` | دو ویرایش موازی مقاله/صفحه با پایهٔ یکسان → یکی ۲۰۰ یکی ۴۰۹؛ پایهٔ مفقود/نامعتبر→۴۰۰، قدیمی→۴۰۹؛ بازگردانی نسخه؛ ویرایش محتوای تأییدشده → ابطال تأیید (IN_REVIEW)؛ انتشار گروهی پس از ویرایش → FAILED با علت؛ گارد نسخهٔ بسته در لحظهٔ اجرا |
| مالکیت اجرا | `suites/worker-ownership.ts` | دو claim موازی بسته → دقیقاً یکی؛ **مکث/ادامهٔ worker قدیمی**: پس از واگذاری مالکیت، touch/finalize قدیمی هرگز نمی‌نویسد؛ تلاش مجدد بستهٔ نیمه‌ناموفق → موفق‌ها SKIPPED و publishedAt دست‌نخورده |
| مجوز تنظیمات | `suites/settings-rbac.ts` | PUT معتبر viewer/author → ۴۰۳ با **اثبات بی‌تغییری DB**؛ کلید غیرمجاز ذخیره نمی‌شود |
| کوکی Secure | `suites/cookie-secure.ts` | قرارداد اعتماد به پروکسی: `x-forwarded-proto` hop نخست → Secure؛ HTTP خام → بدون Secure؛ HttpOnly/SameSite=Lax همیشه |
| رسانه | `suites/media-validation.ts` | فایل جعلی با MIME جعلی → ۴۱۵ بدون ذخیره؛ PNG خراب → ۴۱۵؛ PNG سالم → ذخیرهٔ کامل |

## معماری

```
tests/harness/
├── run.ts        هماهنگ‌کننده: DB موقت → سرور dev مجزا (پورت ۳۲۱۱) → سویت‌ها → خلاصه
├── setup.ts      ساخت دیتابیس موقت با prisma db push + فیکسچر
├── fixture.ts    دادهٔ پایه (۵ نقش، مقالات در وضعیت‌های مختلف، آزمایش و تخصیص، بستهٔ نیمه‌ناموفق)
├── http.ts       کلاینت API با مدیریت کوکی نشست
├── checks.ts     چارچوب چک‌ها (assert/assertEquals/check + خلاصه)
├── config.ts     مسیرها و پورت‌ها (همه نسبی به ریشهٔ مخزن)
└── suites/       هفت سویت بالا
```

نکات فنی:

- سرور تست با `DATABASE_URL` موقت و `NEXT_DIST_DIR=.next-harness` اجرا می‌شود تا با سرور توسعهٔ جاری (پورت ۳۰۰۰، پوشهٔ `.next`) تداخل نکند.
- سویت‌های کتابخانه‌ای (مالکیت اجرا، تبدیل موازی) مستقیماً توابع واقعی `src/lib` را روی دیتابیس موقت اجرا می‌کنند — همان کدی که در production اجرا می‌شود.
- محدودیت نرخ ورود (۱۰ تلاش در ۱۰ دقیقه) به‌دلیل راه‌اندازی تازهٔ سرور در هر اجرا، مشکل‌ساز نیست؛ هارنس ۸ ورود انجام می‌دهد.
- سناریوی «مکث worker» با عقب‌بردن مصنوعی `heartbeatAt` (۱۲۰ ثانیه > آستانهٔ ۹۰ ثانیه) شبیه‌سازی می‌شود — بدون sleep واقعی؛ سریع و قطعی.
