## معرفی

این پروژه یک سیستم مدیریت محتوا (CMS) مدرن است که با تمرکز بر زبان فارسی و طراحی راست‌چین ساخته شده است. هدف، ارائه‌ی یک «سیستم عملیاتی» کامل است؛ نه صرفاً مجموعه‌ای از فرم‌ها. محور اصلی معماری، زنجیره‌ی زیر است:

> هویت ← دسترسی ← داده ← عملیات ← بازبینی و انتشار ← ثبت تغییرات ← پایش ← بازیابی ← سنجش نتیجه

قابلیت‌های کلیدی:

- رابط کاربری کاملاً فارسی و راست‌چین با فونت [وزیرمتن](https://github.com/rastikerdar/vazirmatn)
- تقویم جلالی برای نمایش تاریخ‌ها و ذخیره‌سازی UTC در پایگاه‌داده
- حالت روشن و تاریک (Dark / Light)
- طراحی واکنش‌گرا برای موبایل و دسکتاپ
- جست‌وجو و فیلتر پیشرفته در تمام فهرست‌ها
- ثبت گزارش فعالیت (Audit Log) برای تمام عملیات مهم

## امکانات

### داشبورد و کارهای من
- نمای کلی از وضعیت سیستم شامل آمار مقالات، کاربران، دیدگاه‌ها، بازدیدها و نمودارهای روند
- «کارهای من»: وظایف اختصاص‌یافته به کاربر جاری با نشان تعداد و اولویت‌بندی (فوری / عادی / کاری که منتظر من است)
- علاقه‌مندی‌ها (Favorites) برای دسترسی سریع به محتوای پرکاربرد

### مدیریت محتوا
- **مقالات**: ایجاد و ویرایش با ویرایشگر پیشرفته (MDX Editor)، تصویر شاخص، دسته‌بندی، برچسب و تنظیمات SEO
- **چرخه‌ی انتشار**: پیش‌نویس → در انتظار بازبینی → نیازمند اصلاح → تأییدشده → منتشرشده → بایگانی
- **نسخه‌بندی**: ثبت نسخه‌های مختلف مقاله و امکان بازگشت به نسخه‌های قبلی
- **صفحات**: مدیریت صفحات ایستا با وضعیت انتشار و پیش‌نمایش سایت (`site-preview`)
- **دسته‌بندی و برچسب**: سازمان‌دهی محتوا با رنگ و اسلاگ یکتا؛ دسته‌بندی درختی (والد–فرزند) با جلوگیری از چرخه
- **دیدگاه‌ها**: تأیید، رد و پاسخ به دیدگاه‌ها + گفت‌وگوی موردها در پنل (`comments-panel`)
- **بازارچه‌ی رسانه**: آپلود و مدیریت فایل‌ها با پیش‌نمایش و انتخابگر رسانه در ویرایشگر

### انتشار و یکپارچگی محتوا (مرحله ۲ و ۳)
- **بسته‌های انتشار**: انتشار یک‌جا و منسجم چند آیتم وابسته (مقاله + صفحه + رسانه + منو) با اتصال به نسخه‌ی مشخص، بررسی آمادگی، تاریخچه و مسیر برگشت
- **الگوهای محتوا**: قالب‌های نسخه‌بندی‌شده با جای‌نگه‌دار (Placeholder) و ساخت محتوا از روی نسخه‌ی قفل‌شده
- **واژه‌نامه برند**: واژه‌های رسمی/غیررسمی، معادل پیشنهادی و شدت نقض (ممنوع / هشدار / پیشنهاد) با محدوده‌ی اعمال و استثناهای تعریف‌شده؛ بررسی خودکار هنگام ذخیره
- **موارد مشابه**: کشف داده‌های تکراری (دسته/برچسب/مقاله شبیه) و ادغام امن با لاگ کامل تغییرات و امکان رد کردن مورد
- **سلامت محتوا**: پایش دوره‌ای (لینک شکسته، تصویر بدون alt، محتوای کهنه و…) با فهرست چشم‌پوشی و امتیاز سلامت
- **مرکز عملیات**: گردش کارهای طولانی (ادغام، انتشار گروهی و…) با وضعیت، لاگ مراحل، تلاش مجدد، لغو و گزارش نهایی
- **بازارچه‌ی تغییرات (Redirects)**: مدیریت ریدایرکت‌ها برای حفظ مسیرهای قدیمی

### همکاری و پشتیبانی (مرحله ۳)
- **راهنمای نقش‌محور**: دستورالعمل گام‌به‌گام متناسب با نقش کاربر، همراه با پیشرفت گام‌ها (GuideProgress)
- **گزارش‌های پشتیبانی**: ارسال تیکت تشخیصی از داخل پنل — به‌همراه سیستمی که «چه کسی، کجا، با چه مجوزی» را ثبت می‌کند تا گزارش‌ها قابل پیگیری باشند
- **اعلان‌ها و فعالیت‌ها**: اطلاع‌رسانی رویدادها و تاریخچه‌ی کامل تغییرات سیستم

### سنجش نتیجه محتوا (مرحله ۴)
- **اهداف و نتایج محتوا**: تعریف هدف با قرارداد شاخص شفاف (صورت / مخرج / پنجره‌ی انتساب / بازه / مسئول)، رویدادهای استاندارد (`page_view`, `conversion` و…)، قیف ساده، روند و کیفیت داده
- **اصل تفسیر**: تغییر نشان داده می‌شود اما اثر بدون آزمایش اثبات نمی‌شود؛ «داده نداریم» ≠ «نتیجه‌ی صفر»
- **شبیه‌ساز ترافیک نمایشی**: برای اعتبارسنجی قرارداد رویداد، با نشانه‌ی «شبیه‌سازی‌شده» و جداشدن از داده‌های واقعی

### آزمایش A/B (مرحله ۴)
- **تعریف آزمایش**: فرضیه‌ی مشخص، نسخه‌های ثابت (کنترل / درمان)، برنامه‌ی نمونه و شاخص اصلی + شاخص‌های محافظ
- **انتساب پایدار**: گروه‌بندی یکنواخت بر اساس کلید پایدار، بدون تغییر گروه در طول آزمایش
- **ثبت واقعی نمایش**: رخداد Expose فقط هنگام دیده‌شدن واقعی نسخه ثبت می‌شود
- **بررسی فنی پیش از شروع**: نسخه، تأیید محتوا، «یک آزمایش برای هر محل»، تست A/A و سلامت شاخص‌ها
- **نتایج زنده**: عدم‌قطعیت، SRM و شاخص‌های محافظ — بدون اعلام برنده‌ی زودهنگام
- **پایان طبق برنامه**: تصمیم انسانی با ثبت دلیل و محدودیت‌ها؛ انتشار خودکار انجام نمی‌شود

## راه‌اندازی

پیش‌نیازها: [Bun](https://bun.sh/) نسخه ۱.۱ یا بالاتر

```bash
# ۱. نصب وابستگی‌ها
bun install

# ۲. ساخت پایگاه‌داده از روی اسکیما
bun run db:push

# ۳. تولید کلاینت Prisma
bun run db:generate

# ۴. درج داده‌های نمونه
bunx tsx prisma/seed.ts

# ۵. اجرای سرور توسعه
bun run dev
```

سپس پنل روی `http://localhost:3000` در دسترس است.

## نقش‌ها و سطوح دسترسی

کنترل دسترسی مبتنی بر نقش (RBAC) با چهار سطح و مجوزهای دانه‌ریز (از جمله `analytics.view` برای ماژول‌های مرحله ۴):

| نقش | توضیح |
|---|---|
| `ADMIN` | دسترسی کامل به همه بخش‌ها، مدیریت کاربران و تنظیمات |
| `EDITOR` | بازبینی، تأیید و انتشار محتوا و مدیریت دسته‌بندی‌ها |
| `AUTHOR` | ایجاد و ویرایش مقالات خود (چرخه پیش‌نویس تا در انتظار بازبینی) |
| `VIEWER` | دسترسی فقط‌خواندنی |

چرخه وضعیت کاربر: `دعوت‌شده (INVITED)` ← `فعال (ACTIVE)` ← `تعلیق‌شده (SUSPENDED)` / `غیرفعال (DISABLED)`

## چرخه‌ی انتشار مقاله

```
DRAFT (پیش‌نویس)
   ↓ ارسال برای بازبینی
IN_REVIEW (در انتظار بازبینی)
   ↓ تأیید                ↓ درخواست اصلاح
APPROVED (تأییدشده)    NEEDS_REVISION (نیازمند اصلاح)
   ↓ انتشار                 ↓ بازگشت به بازبینی
PUBLISHED (منتشرشده) ←───────┘
   ↓ بایگانی
ARCHIVED (بایگانی)
```

هر تغییر وضعیت در گزارش فعالیت ثبت می‌شود و نسخه‌های قبلی مقاله قابل بازیابی هستند.

### چرخه‌ی آزمایش A/B

```
DRAFT (پیش‌نویس آزمایش)
   ↓ بررسی فنی: نسخه، تأیید محتوا، یک آزمایش برای هر محل، A/A، شاخص‌ها
RUNNING (در جریان) — انتساب پایدار + ثبت Expose واقعی
   ↓ پایان طبق برنامه (نه بر اساس «برنده‌ی زودهنگام»)
ANALYZING (تحلیل) — نتایج با عدم‌قطعیت، SRM و شاخص‌های محافظ
   ↓ تصمیم انسانی با ثبت دلیل
DECIDED (تعیین‌شده) — اجرای تصمیم خودکار انجام نمی‌شود
```
